# Axiom 前端艺术方向：活页

更新时间：2026-08-24

这份文档定义 Axiom 的产品感知与交互秩序。它不是主题说明，也不是一组可复制到任何 AI 产品上的颜色和组件。

## 为什么推翻上一版

上一版“墨与光”解决了卡片墙和蓝紫科技风，却仍然保留固定侧栏、图标菜单、大标题工作台和浮层卡片等旧骨架。深色、细线、衬线大字与微光组合在一起，也形成了明显的生成式设计套路。

问题不在某个色值，而在界面仍然要求用户先理解页面，再完成事情。

本版从以下判断重新出发：

```text
Axiom 不是装着功能的容器。
Axiom 是一张始终摊开的私人认知工作面。
```

## 核心形态：Living Folio

“活页”同时包含三种经验：

- 编辑出版物的网格和精确层级，让复杂内容可以被快速扫读。
- 手卷与档案的连续时间，让输入、行动和回看属于同一段经历。
- 实验谱记的节奏和边注，让状态通过位置、停顿和记号表达。

它不是复古纸张皮肤。纸面感来自稳定基底、纤维般微差、清楚墨色和可重复形成空间记忆的排版规则。

## 低摩擦原则

### 打开即开始

默认落在“此刻”，首屏只有一个主要焦点和一个可立即执行的动作。系统内部对象不会先变成导航选择题。

### 输入不先分类

任意位置一次触发进入记录平面。文字、链接和文件先被接住，再由系统理解；`N` 是桌面快捷入口，移动端记录动作固定处于拇指可达区。

### 找回不先筛选

资料库打开后可直接输入，输入两个字符后自动找回。精确与相近含义只有一个轻量切换；类型、状态和来源条件默认收起。桌面按 `/` 或 `Ctrl/Cmd + K` 直接进入找回。

### 结果留在原语境

打开记录、行动、记忆和决定时使用详情抽屉，不强迫用户离开当前阅读位置。Atlas 聚焦也从全局空间原地收束，不跳入另一套产品。

### 次级能力不是工作台

行动、记忆、决定、时间和回顾只在语境中自然出现。需要完整管理时从“索引”进入；结构校准、自动化和系统状态进一步降级为治理能力。

## 视觉语法

### 纸、墨、矿物色

- 主表面是偏冷的中性纸白，不使用米黄复古滤镜。
- 正文是接近黑绿的墨色，不使用纯黑造成数字屏幕感。
- 朱红只标记意图与入口。
- 苔绿标记连续性、确认与完成。
- 钴蓝标记找回、远端关系与空间。
- 紫色标记尚未收束的判断。
- 色彩面积很小，必须对应真实语义。

Atlas 保留深色空间，因为它承担远观关系的任务；明暗切换是产品空间变化，不是全局暗色主题。

### 网格与边注

- 页面依靠比例、细线和空白组织，不使用浮卡与阴影分组。
- 标题、正文、索引和状态分别使用衬线、无衬线和等宽字，但字距始终为零。
- 左侧边注说明信息处于什么语境；右侧记号承载动作或完成状态。
- 列表项是连续索引，不是重复卡片。
- 交互焦点使用与当前语义一致的细线，不出现浏览器默认粗框。

### 物理微差

背景只绘制静态、确定性的细小纤维与少量对位线。它帮助纸面摆脱纯色网页感，但不能成为装饰图案，也不持续消耗动画资源。

### 动效

- 页面切换只发生短距离位移与显隐。
- 索引和记录平面像揭开一张活页，从边缘进入。
- 常态页面没有持续呼吸、漂浮、光斑或粒子表演。
- Atlas 的相机和聚焦动效只服务空间理解。
- `prefers-reduced-motion` 下所有非必要运动都可移除。

## 核心产品空间

### 全局壳

桌面端顶部是一条章节索引：Axiom、此刻、资料库、记录、Atlas、找回和索引。它不占据侧栏，也不让对象类型成为一级入口。

移动端保留五项底部节奏带：此刻、资料库、记录、Atlas、索引。记录位于中心，但仍是动作而不是页面。

次级索引以整页目录出现，不采用弹出菜单或卡片抽屉；它明确显示这些能力处于主要体验背后。

### 此刻

“此刻”是一张行动谱面：

1. 左侧边注给出推荐依据和环境线索。
2. 中央只呈现一个当前行动、原因与所属承诺。
3. 右侧用完成记号结束行动，不再增加按钮组。
4. 本周承诺沿同一张谱面向下展开。
5. 备选行动、待判断边注和最近痕迹依次出现。

界面不显示统计卡。数字只在周进度、待判断数量和底部状态行中出现。

### 资料库

资料库是一册可直接输入的生长索引：

- 搜索线是页面主体，不被表单卡包裹。
- 输入停顿后自动找回，不要求额外点击搜索。
- 结果按原始记录、行动、记忆和决定编排为连续章节。
- 来源、状态和时间是边注，不抢标题。
- 复杂筛选和批量治理只在需要时展开。
- 项目脉络是同一资料库的另一种编排，不是新的工作台。

### 次级对象索引与上下文页

行动、记忆和决定的完整管理面不是三个平级工作台，而是同一本活页中的三册薄索引：

- 条目连续排列，以细线、边注和少量矿物色表达状态，不使用卡片容器。
- 数字是账册页码般的总量提示，不组成仪表盘。
- 新建表单默认折叠成一行，需要时原地展开；浏览与维护不被表单长期占据。
- 打开条目后，右侧进入纸面上下文页，保留当前索引位置和真实关联。
- 主动作位于上下文页底部，历史、来源与治理信息按需展开，不先向用户倾倒元数据。

原始记录使用同样的纸面上下文页。行动、记忆、决定和记录因此共享“先扫读、再展开、原地返回”的肌肉记忆，而不是四套对象后台。

### Atlas

Atlas 是深色全屏关系场：

- 全局 3D 使用点状节点、真实三维分层和关系驱动距离。
- 标签只保留根、真实主线和主要主题，避免中心重叠。
- 结构线中性；语义线使用低饱和灰红到雾蓝方向色。
- 点击节点后收束为 2D 局部语境，一跳清楚、二跳与外围次联系弱化。
- 工具贴边出现，图谱始终占据视觉主体。

### 记录

记录是一整张写作平面，不是弹窗卡片。输入区域在桌面和移动端都自动获得焦点；Enter 提交，Shift + Enter 保留换行，附件可通过选择、粘贴或拖入加入。

### 私有入口

入口像一本私人档案的封面：品牌、编号、访问线和登记标记构成固定版式。它不展示营销信息，也不使用常规居中登录卡。

## 必须避免

- 深色发光、渐变光斑、玻璃拟态和“AI 科技感”作为默认人格。
- 固定侧栏、图标加文字的后台导航、十三个平级工作台。
- 巨大无意义标题、功能说明文案和营销式价值主张。
- 卡片墙、卡片套卡片、徽章堆叠和统计仪表盘。
- 为艺术感牺牲移动端可达性、阅读密度或真实操作速度。
- 所有节点与关系同时动画。
- 为填满画面而伪造关系、装饰线或随机内容。

## 验收问题

每次修改主前端都要回答：

1. 用户从打开页面到完成当前动作需要几次选择。
2. 去掉颜色后，位置、字号和空白是否仍能表达层级。
3. 这段文字是在呈现真实内容，还是在解释界面本身。
4. 同一对象打开后能否回到原来的阅读位置。
5. 移动端是否保持一只手可达、无横向溢出、无文字遮挡。
6. Atlas 画布是否非空、正确取景，并保留全局到局部的空间连续性。
