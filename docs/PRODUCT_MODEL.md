# Axiom 产品模型

更新时间：2026-08-21

这份文档定义 Axiom 对用户呈现的产品形态和内部认知逻辑。页面、功能和数据模型的新增都必须服从这里，而不是反过来扩张一级入口。

## 一句话定义

Axiom 是一个以“此刻”为中心的个人外脑：它持续接住输入、保留事实、理解上下文、推动下一步，并从行动结果中修正对用户的认识。

Axiom 不是笔记、任务、记忆、决策和图谱工具的集合。这些是系统内部理解信息的对象，不是用户必须学习的导航结构。

## 用户面对的形态

Axiom 只有三个主要目的地和一个全局动作：

- **此刻**：默认工作面，回答现在最应该关注什么、为什么、下一步是什么、需要想起什么。
- **资料库**：统一找回记录、文件、记忆、任务和决策；对象类型只是筛选视角。
- **Atlas**：资料库和个人经历的空间投影；全局为 3D 认知地图，聚焦后进入 2D 局部语境。
- **记录**：任何位置都能触发的全局动作，不是独立工作台，也不要求用户预先分类。

任务、记忆、决策、处理队列、时间线和回顾只在相关上下文中出现。自动化、结构编辑和系统治理属于次级管理能力。

## 此刻

“此刻”是唯一主工作面，不是任务列表或统计看板。它按视觉优先级呈现：

1. 一个当前焦点。
2. 一个可以立即开始的下一步。
3. 少量备选行动。
4. 等待用户判断的记忆或决策。
5. 最近进入外脑的上下文。

系统应减少选择成本，而不是把所有可能行动同时展示出来。

## 资料库

资料库承担“找回”，而不是“分类管理”。用户可以按主题、人物、项目、时间或对象类型查看内容，但不需要先选择记忆库、决策台或任务台。

项目或生活线的详情应汇合目标、材料、事实、行动、决定、进展和历史，而不是把它们拆散到不同模块。

## Atlas

Atlas 回答“这些事情之间是什么关系”。它是同一批事实和对象的空间视图，不维护另一套真相。

- 全局 3D 用于观察长期结构、生活线、主题分区和整体距离。
- 关联越强，节点越近；语义区域保留真实三维层次。
- 聚焦节点后转为 2D 局部图，一跳关系清晰，二跳关系和外围次联系弱化。
- 关系必须有来源或明确标记为推断，不能由前端为了画面丰富而伪造事实。

## 内部认知循环

```text
发生了什么
→ 它与什么有关
→ 它意味着什么
→ 是否需要行动
→ 行动结果如何
→ 从结果中学到了什么
```

系统始终区分：

- **原始事实**：用户真正输入、上传或做过的事情，不被 AI 改写。
- **AI 推断**：带来源、置信度和适用范围的候选理解。
- **用户意图**：由用户确认的目标、承诺和选择。
- **执行结果**：事情后来是否发生，以及真实反馈是什么。

读取和总结可以自动发生；形成长期记忆、改变承诺和执行外部写操作需要与风险相称的确认。

## 行动与记忆

下一步不只按截止日期排序，还应考虑目标贡献、当前时间与精力、解锁作用、不处理的后果、启动成本和近期惯性。默认只突出一个主要行动。

并非每条记录都成为长期记忆。长期记忆必须保留来源、情境、置信度、可能的过期时间和后续证据，并只在相关时刻自然出现。

## 产品边界

- **MemoryGuard** 是独立的鸿蒙杯项目。Axiom 可以吸收其记忆预览、确认、审计和可撤销原则，但不把它做成新入口或运行依赖。
- **Learning Board / 白板** 是火山杯竞赛项目。Axiom 以后可以把成熟的画布能力作为某个项目或学习上下文的视图，但白板不是 Axiom 一级工作台。
- **Cosmos** 是 Atlas 的结构编辑和调试能力，不与 Atlas 并列成为用户产品。
- **聊天** 是上下文中的交互方式，不是覆盖全产品的悬浮入口。

## 判断新功能是否属于主线

新功能至少应改善下面一项，否则不进入 Axiom 主界面：

1. 记得更准确，并保留依据。
2. 更快找到当前需要的上下文。
3. 把长期目标转成此刻可执行的下一步。
4. 通过结果和复盘证明系统在变得更懂用户。
